# 下一阶段：四轮编码器输出与实机验证计划

## 1. 阶段目标与范围

前置：[初始航向实机测试报告](debug_log/10_2026-11-11_初始航向基准实机测试报告.md)。
本阶段完成一个功能：**可靠地读取并记录四个电机的累计编码器位置和实际转速**。
当前为实施计划，编码器新接口、遥测与监视脚本尚未实现。

本阶段不实现融合定位、自动行驶、新版居中或轮速闭环；不以指令转速冒充实测转速。
编码器描述轮/电机转动，不能单独证明车辆在地面移动了相同距离。

## 2. 实现顺序

1. 在唯一电机管理者 `ChassisDrive` 内增加读取能力；显式确认编码器单位，
   输出电机累计角度（建议度）与实际 RPM，不依赖设备默认单位。
2. 按工程统一顺序 **FL/FR/RL/RR**（端口 **1/3/2/4**）输出状态快照，
   包含原始位置、实测速度、逐轮有效性和读取时间戳；读取失败不能当零位置/零速。
3. 通过模块公开接口读取快照，main 只调度；后续归一化方向使用配置中的符号，
   同时保留原始读数，避免把电机坐标与车体坐标混淆。
4. 仅在 `diag/telemetry.cpp` 定义遥测，配套只读监视/CSV 工具、字段契约检查与文档。
5. 提供不执行电机运动的传感器测试路径，并在整车配置中统一选择测试模式。
   **不能通过直接关闭航向测试开关来采集，否则会恢复当前遥控/居中流程。**
6. 完成构建、架构规则、数据有效性/方向换算/单位等可脱离硬件的测试，交付实机步骤并停止。

累计位置初值不要求为零：日志保留原始累计量，以采集起点计算差值。
是否需要显式重设位置原点，待读取路径验证后决定，避免读数接口顺手修改设备状态。

## 3. 第一轮实机验证（编码器读取）

| ID | 操作 | 观察 | 验收依据 |
| --- | --- | --- | --- |
| E-01 | 小车固定、四轮静止 20s | 四轮位置和转速、有效位、时间戳 | 无明显位置跳变；速度接近零；失败不能显示成有效零值 |
| E-02 | 架空后依次缓慢手转每个轮子 | 端口/轮位与对应计数变化 | 主要变化的是对应轮；不将串口显示顺序误作接线顺序 |
| E-03 | 给轮子作标记，正反各一圈 | 角度增量、符号、回原位残差 | 按直驱 1:1 与显式度单位，应接近 ±360°；误差据实记录，不先编造精度指标 |
| E-04 | 连续两次采集同一次程序运行 | 原始累计位置、日志起点差值 | 采集工具启动/关闭不重设设备位置 |
| E-05 | 断开一路设备再恢复（静止条件下） | 逐轮有效性和其余三路 | 故障明确标记，其他轮正常，不把错误值积分为位移 |

手转应缓慢，不强行扳动有明显阻力的传动；无法手转时停止该项，另行设计低速单轮测试。
日志应记录轮位、动作起止时间、实际圈数/方向，便于与 CSV 对照。
只有 E-01..E-05 的实际结果足够明确后，才考虑低速带动力测试。

## 4. 阶段停止点

- 输出功能实现并通过软件检查后，先停止开发，交由用户完成上述实机采集。
- 根据数据确认端口映射、单位、方向、累计量与失效处理，写出本阶段报告。
- 不同时推进位置估计，以免将“计数读取错误”和“定位算法误差”混在一起。

## 5. 后续路线（本轮不实施）

1. 编码器 + 固定航向：先完成短程位移预测，直行/后退/横移与卷尺对照。
2. 补齐 ToF 距离/速度各自的有效性与质量信息，再做观测校正。
3. 融合定位通过后重建单墙/双墙居中，先直走廊，后开口与转角。
4. 每完成一项可观察功能都先停下实测，软件通过与实车通过分别记录。
