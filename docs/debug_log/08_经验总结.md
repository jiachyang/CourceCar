# 08 经验总结（本次 debug 通用教训）

## A. 定位方法

1. **先定量、再动参数**。这次最大的收益是"把 PID 内部量全回传"，
   直接看到 `err / P / I / D / corr / tw / 轮命令 / 轮实测`，才定位到"命令被丢弃"。
2. **区分"设定点"和"输出"**。目标航向 `ht` 是设定点，不会驱动轮子；
   驱动轮子的是 PID 输出 `tw`。排障时盯输出。
3. **看"命令 vs 实测"是否一致**。图里 `总输出 -13` 却 `轮命令 0`
   一眼就暴露了量化问题。
4. **重启能"治好"的，是状态问题**（如积分 windup、旧目标锁存）。

## B. PROS / VEX 具体坑

1. **IMU 就绪判定**：`get_status()==ImuStatus::ready` 不成立（实测返回 18/19/1），
   要用 **`is_calibrating()`**。
2. **`move_velocity` 只接受整数 rpm**（`int32_t`）：小修正会被 `lround` 抹成 0，
   造成控制死区。要么改 `move_voltage`（支持小数、但开环），
   要么用"最小幅值抬升/抖动"，要么上软件轮速 PI。
3. **`get_rotation()` 已做过零偏补偿**，别再扣一次（二次补偿反而制造漂移）。
4. **编码器 1800 ticks/圈（0.2°）**；`get_actual_velocity()` 是 double（可读小数）。
5. **`printf` 走用户口**，PROS 会加 `sout` 之类前缀，解析要在行内匹配标记。
6. **固定周期用 `pros::Task::delay_until()`**，别用 `delay(20)` 累加误差。

## C. 控制 / 整定

1. **硬死区不可取**：会造成输出 0↔大值硬切、颤振。要死区就用"软死区"。
2. **积分要防 windup**：状态限幅、主动旋转时清零；`Ki` 符号别弄反（曾出现 `Ki=-0.01`）。
3. **输出量化会形成死区**：命令分辨率 × 增益 决定稳态误差下限。先算清
   "最小命令 ↔ 车体自转角速度 ↔ 每周期转角"，再设增益。
4. **纯 P 有稳态误差**（P 顶住扰动）；要消它得加 `Ki` 或抵消扰动。

## D. 工程习惯

1. **改参数只改配置**（`*_config.hpp`），不散落在 .cpp；`invert*` 就是为实测反转准备的。
2. **每次改动都跑**：`bash scripts/test_native.sh`（IK / 航向控制器 / 遥控映射）+ `pros make`。
3. **回传要够用**：字段太少会误判（如把小数命令显示成 0）。
4. **文档与代码同步**：端口/需求变更要更新 `docs/chassis_requirements.md` 的修订记录。
5. **保留原始日志**：`--csv` 存全字段，便于离线复算。

  若要更好，需**软件轮速 PI**（闭环 + 小数），或"最小幅值抬升"策略。
