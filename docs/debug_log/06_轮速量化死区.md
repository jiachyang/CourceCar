# 06 轮速量化死区（本次最核心的根因）

## 6.1 现象

诊断表里出现自相矛盾：

```
航向误差 -22 mrad      （车离目标约 1.26°）
总输出   -13 mrad/s    （PID 确实算出了修正）
施加ω    -13
轮命令  FL FR RL RR = 0, 0, 0, 0    ← 但四个轮子命令都是 0
陀螺角速度 +0                        ← 车没转
```

**PID 有输出，轮子却收不到 → 修正被"吃掉"，航向卡在 1.26° 不动。**

## 6.2 定位

`src/chassis/chassis_drive.cpp` 原来：

```cpp
motors_[i].move_velocity(static_cast<std::int32_t>(std::lround(cmd[i])));
```

而 PROS 的 `move_velocity` 签名就是**整数 rpm**：
`move_velocity(const std::int32_t velocity)`（`include/pros/motors.hpp`）。

算一遍那条 −13 mrad/s：

```
ω = 0.013 rad/s
纯自转轮缘线速度 s = R·ω = 0.1475 × 0.013 = 0.00192 m/s
轮速 = s / (2π/60 · r) = 0.00192 / 0.005236 = 0.366 rpm
lround(0.366) = 0        → 电机收到 0
```

**0.37 rpm 被 `lround` 变成 0，四个轮的修正全部丢失。**

→ **航向量化死区**：要凑够最小 1 rpm，需 `ω = 0.0355 rad/s = 35.5 mrad/s`；
`Kp=0.5` 时要产生它需误差 `35.5/0.5 = 71 mrad ≈ 4°`。误差小于此时，轮子完全不动作。

（另外，遥测里 `轮命令` 用 `static_cast<int>()` 截断打印，把 0.37 也显示成 0。）

## 6.3 解决：改用 `move_voltage`（支持小数）

`src/chassis/chassis_drive.cpp`：

```cpp
const double rpmToMv = config_.motorRpmToMillivolt;   // 60 mV/rpm
double mv = cmd[i] * rpmToMv;
mv = std::max(-12000.0, std::min(12000.0, mv));
motors_[i].move_voltage(static_cast<std::int32_t>(std::lround(mv)));
```

`include/chassis/chassis_config.hpp`：

```cpp
inline constexpr double kMotorRpmToMillivolt = 60.0;  // 12000mV / 200rpm(green)
```

分辨率从 **1 rpm** 降到 **1 mV ≈ 1/60 rpm ≈ 0.017 rpm**。

**遥测**：轮命令/轮实测改成 **milli-rpm（×1000）**回传，诊断表按 rpm 显示一位小数。

## 6.4 分辨率换算（20ms 周期，最小 1 rpm）

| 量 | 数值 |
| --- | --- |
| 1 rpm 轮 → 车体自转 | `(2π/60·r)/R = 0.0355 rad/s = 35.5 mrad/s = 2.03°/s` |
| 一个 20ms 周期的最小转角 | `0.0355 × 0.02 = 0.71 mrad = 0.041°` |
| 对应轮子每周期转角 | 0.12°（= 0.6 个编码器 tick，0.2°/tick） |

## 6.5 取舍与后续

`move_voltage` 是**开环**（绕过电机内部速度环）：
- 轮速不再被速度环调稳，四轮一致性/直行会变差；
- 极低速仍有**电压死区**（mV 太小推不动）。

若要"既支持小数、又闭环"，正解是给每轮加**软件轮速 PI**（目标 rpm → 输出 mV，带积分越过电压死区）。

**另一条轻量替代**：保留 `move_velocity`，但用"**最小幅值抬升**"——
四舍五入，**仅当结果被舍成 0 且命令非零时**才进成 ±1。
效果：消掉死区，稳态误差由 ~1.3° 变成 ~0.1° 的极限环（< 0.5°），
且不像 `ceil` 那样给大命令引入 +δ 偏置。

## 6.6 编码器信息

- V5 Smart Motor 内置编码器：**1800 ticks/圈 = 0.2°/tick**；PROS 默认单位 degrees。
- 换算到本车：1 个轮 tick ≈ 车体自转 `0.2°·(r/R) ≈ 1.18 mrad`。
- 即**测量分辨率（0.07°）远细于命令量化**，所以问题出在命令侧，不是编码器测不出。
