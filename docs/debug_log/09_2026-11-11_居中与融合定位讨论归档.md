## 3. 当前实现的问题与证据

### 3.1 双墙可信是持续居中的前提，缺少正常的单墙保持能力

[LaneKeeper::evaluatePair](../../src/modules/lane_keeper.cpp) 要求：两侧有效、分类非 FAR/UNKNOWN、
两侧滤波距离均小于 150 mm、几何宽度在默认 0.37–0.70 m 内，才判定可信走廊。

按现有固定墙中心线地图、车头朝地图上方、默认传感器顶点半径 0.1803120669 m，
在起点 S=(4,7) 格心计算的前/后/左/右理论距离约为：

| 前 | 后 | 左 | 右 |
| ---: | ---: | ---: | ---: |
| 494.7 mm | 44.7 mm | 494.7 mm | 44.7 mm |

这是忽略墙厚、安装误差和实际光束误差的几何计算，不是实测。
起点左右墙距已经不满足双墙可信条件；路线中还有单墙、开口和短墙结束等情况。
所以双墙距离差控制不能覆盖完整路线。

### 3.2 过近避让依赖双墙可信

[LaneStateMachine::update](../../src/lane/lane_state_machine.cpp) 只有在 `credible` 分支中才会进入 `TOO_CLOSE`。
一侧危险而另一侧不可用时，不能独立触发该模式。

[test_lane_keeper.cpp](../../tests/native/test_lane_keeper.cpp) 已有用例：一侧 5 mm、另一侧读取失败，
期望 `INSUFFICIENT_DATA` 且横向命令为零。该测试证明现有行为符合旧契约，不能证明满足新防碰需求。

### 3.3 现有航向目标不能充当固定的迷宫原始航向

- [Chassis](../../src/modules/chassis.cpp) 已有 5000 ms 延迟，但在满足条件的首次 `update()` 中锁存。
- 正常传感器/底盘控制循环在 `opcontrol()` 内，不能保证恰好在上电 5 秒采到原始航向。
- `Chassis::stop()` 清除航向目标；[HeadingController](../../src/chassis/heading_controller.cpp) 在主动旋转期间持续重锁目标。
- 当前没有独立、持续保存的迷宫初始航向 `ψ₀`。

### 3.4 固件未接入位置估计，ToF 速度没有传到下游公共快照

- 当前正常固件链路没有产出 `(x,y,θ)` 的定位模块。
- LaneKeeper 的航向输入目前主要用于诊断，不参与坐标变换或位置估计。
- [DistanceArray](../../src/modules/distance_array.cpp) 已调用 `get_object_velocity()`，记录 `velocityMmS`。
- [core::RangeSample](../../include/core/range_types.hpp) 没有速度字段，`toRangeSnapshot()` 没有转发速度。
- `DistanceReading` 的速度默认值为零，没有独立速度有效位；后续融合需要区分“真零速”和“读取失败”。
- 编码器累计位移尚未在当前底盘公开快照中提供；现有 `readWheelRpm()` 读取的是实际转速。

### 3.5 用瞬时运动命令选墙，缺少稳定路线方向

- 当前有平移时依据基础命令更新方向，停车后沿用最后方向。
- 在纵向走廊中横移后停车，可能保留前后组，无法继续按左右墙居中。
- 45° 斜向命令因对齐分数不足而不选组。
- 换对时只清 PD，未同步清除或正确转换上次横向修正；旧修正标量可能沿新的法向施加。

### 3.6 默认停车补偿在现有仿真中产生摆动

当前误差超过 3 mm 时，会把较小的停车纠偏提高到至少 0.08 m/s。
本轮实际运行 `bash sim/run_lane_keeping.sh`，默认 `standstill+20` 场景得到：

- 初始横向偏差 20 mm。
- 统计窗口内偏差峰峰值约 17.1 mm。
- 统计窗口内穿越中心 9 次。

这支持“停车最小速度与接近目标时的制动需要重新设计”的判断；未验证真机摆幅。

### 3.7 防碰与仿真覆盖存在缺口

- [SafetySupervisor](../../src/modules/safety_supervisor.cpp) 默认要求传感器轴与运动方向余弦不小于 0.85。
  45° 运动时四路轴向传感器都可能被排除，现有单测也允许这种情况下保持原速度。
- 当前安全层未根据定位、有限墙段与车身包络检查转角扫掠。
- 浏览器导航仿真是旧版 JS LaneAssist，未同步当前 C++ 固件控制器。
- 顶层 C++ 居中仿真直接调用固件 LaneKeeper，但固定航向，未接入 SafetySupervisor，
  不能验证完整的定位—居中—防碰—航向控制链。

## 4. 讨论中的关键修正：融合应包含 ToF 速度

助手第一轮强调：“仅有左右墙距时，纵向位置无法唯一确定。”
用户指出应结合前后 ToF、编码器、陀螺仪，并利用 ToF 自带速度读数。

修正后的讨论方向：

- 编码器提供连续的位移/速度预测。
- IMU 航向和陀螺仪提供姿态与角速度信息。
- 前后左右 ToF 的距离观测校正位置，速度观测校正平移速度。
- 前后能看到静止墙面时，可以约束纵向位置和速度；短时无有效墙面时继续预测。
- 只有在某方向长时间没有有效位置观测时，才需要明确该方向误差会累积。

不能将“仅左右距离的观测不足”扩大为“整套传感器无法进行纵向融合定位”。

## 5. 候选方案，尚待确认和实现

### 5.1 初始航向与坐标

建议将迷宫原始航向与底盘临时保持目标分开保存：

```text
上电满 5 秒且 IMU 就绪 → 记录 ψ₀
迷宫相对航向 θ = wrap(IMU航向 − ψ₀)
正常比赛期间保持 θ = 0，通过平移改变行进方向
```

IMU 到 5 秒仍未就绪时继续等待；停车、禁用或重新使能保留 `ψ₀`。
这些是建议语义，具体锁存就绪条件与显式重新设零入口尚待确认。
地图坐标与该零点的对应仍依赖起点摆放；不能由 IMU 自动识别地图朝向。

### 5.2 每周期连续融合，先保持结构简单

候选步骤：编码器与 IMU 预测 → ToF 速度校正平移速度 → ToF 距离结合地图校正位置
→ 输出位置、速度及可信程度。

初版可讨论使用简单加权/互补校正；是否采用 EKF、具体权重和门限尚未决定。
不能把同一传感器的距离和速度直接当作完全独立的高可信观测。

在航向对齐、前后光束近似垂直照到静止墙、已统一“靠近为正”的条件下：

```text
前 ToF 速度 ≈ 车体前进速度
后 ToF 速度 ≈ −车体前进速度
纵向速度观测 ≈ (前 ToF 速度 − 后 ToF 速度) / 2
```

这是特定几何下的简式；斜入射、航向变化或命中墙段切换时，要使用相应测量模型。
一路有效也可参与，两路有效且一致时提高权重；没有有效观测时继续预测并降低可信程度。

### 5.3 居中控制减少状态历史

助手提出的候选方式：

| 可用观测 | 候选控制方式 |
| --- | --- |
| 两侧是当前路线的对应墙 | 计算几何中心误差 |
| 只有一侧对应墙 | 保持该墙到目标中心线应有的距离 |
| 两侧均不可用 | 根据估计位置跟踪路线中心线，并降低速度 |
| 任意方向危险过近 | 独立限制靠近障碍的速度，不依赖双墙可信 |

位置误差与融合速度可形成连续的横向控制：

```text
横向修正速度 = Kp × 横向位置误差 − Kv × 横向实际速度
```

误差正方向、坐标系、限幅、静摩擦处理和最终增益尚待设计、测试及标定。
不应重复叠加“墙距纠偏”和“同一墙距已经校正过的位置误差”，以免放大控制。

助手进一步建议：以当前路线中心线为目标，墙距提供局部校正与约束；用户尚未确认这一具体控制选择。

### 5.4 四路职责随路线方向变化

用户明确了四 ToF、编码器和 IMU 联合参与的方向；助手补充建议：
车头始终保持初始方向时，前进/后退主要用物理左右墙居中；横向穿过走廊时，
物理前后 ToF 也应承担相对于行进方向的横向约束。具体选墙依据稳定路线段与地图几何，
不只依赖瞬时速度命令。

### 5.5 转角与仿真

- 候选初版动作：转角前减速，在安全区域完成旧方向制动，再沿新方向平移。
- 防碰考虑实际车身包络、墙厚、墙端点、定位误差和制动距离。
- 仿真应运行与固件相同的 C++ 逻辑，覆盖完整链路。
- 参数应包含安装偏移、距离/速度噪声与偏置、延迟、居中增益、停车处理、制动参数。
- 场景至少包含双墙、单墙、墙段结束、开口、横移、转角、活动挡板、单路故障和打滑。

## 6. ToF 速度与测量质量的待验证点

- VEX 官方说明采用“靠近为正、远离为负”；现有浏览器仿真 `sense()` 使用相反的速度符号，
  其估计器也配套使用该仿真约定。因此内部仿真自洽并不证明与 PROS 真机一致。
- 应先用真机向固定墙靠近/远离核对 `get_object_velocity()` 的符号、单位和延迟。
- 仓库 [测距仪数据-P2.md](../测距仪数据-P2.md) 记录静止速度约 −0.08～0 m/s；
  这是既有测试条件下的记录，不能直接当作四路统一、永久的零偏标定。
- 距离与速度应各自带有效性信息；失败、超量程或无目标不能当作零速。
- 墙端点、开口或目标切换引起的距离变化，不能直接解释为车辆速度。
- 移动物块的相对速度不能直接当作静止墙提供的自车速度观测。
- 近距置信度存在固定值现象，不能简单用统一高阈值剔除所有近距观测。

讨论时核对的外部依据：

- [VEX：Using the Distance Sensor with VEX V5](https://kb.vex.com/hc/en-us/articles/360050696511-Using-the-Distance-Sensor-with-VEX-V5)：速度含义、正负号和量程。
- [PROS：VEX Distance Sensor C API](https://pros.cs.purdue.edu/v5/pros-4/group__c-distance.html)：速度 API 单位 m/s、错误返回及置信度说明。
